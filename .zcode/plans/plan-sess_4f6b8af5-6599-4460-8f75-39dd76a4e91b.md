# OpenChamber → TaskHunter 品牌替换方案

## 已确认的决策
- **个人自用**：外部标识彻底改名，不写老用户迁移代码。
- **更新与服务**：关闭 hosted 更新检查和 npm/GitHub 自更新（防止误装上游构建）；桌面端更新 feed 指向 `jlu-lujing/TaskHunter` 自己的 Releases（没有 release 时自动"无更新"）；relay / APNs 推送 / Linear broker 保留默认值，文档标注"依赖上游基础设施"。
- **Logo**：生成一套 TaskHunter 品牌占位图形（SVG 组件 + 各平台 icon），观感统一，可日后替换。

## 执行步骤

### 第 1 批：批量文本替换（脚本化 sed/python，带保护名单）
一个替换脚本按词形分别处理 `OpenChamber→TaskHunter`、`openchamber→taskhunter`、`OPENCHAMBER→TASKHUNTER`，作用于源码、测试、docs MDX、README/CONTRIBUTING/SECURITY、`.agents` skills、AGENTS.md/CLAUDE.md；跳过保护名单和 lockfile。文件/目录改名：`OpenChamberLogo.tsx`、`components/sections/openchamber/`、`server/lib/openchamber-control|openchamber-sessions/`、`openchamberConfig.ts`、badge 资源、`.agents/skills/openchamber-change-discipline/` 等（用 `git mv`，随后 `bun run dead-code` 检查 import）。

### 第 2 批：外部标识与清单文件手工精修
- `packages/electron/package.json`：build 段（appId、productName、协议注册）、`updater-feed.mjs` feed → `jlu-lujing/TaskHunter`；`main.mjs` 深链协议、CHANGELOG raw URL 指向自己仓库。
- `packages/vscode/package.json`：publisher/name/displayName/全部命令 id/view id/配置键 + `package.nls*.json`、`extension.ts`。
- `packages/*/package.json` + 根 `package.json`：scope、bin、互引 import；然后 `bun install` 重生成 lock。
- `packages/mobile/capacitor.config.ts`、iOS `Info.plist` bundle id、Android `strings.xml`/`build.gradle` applicationId。iOS Xcode target 目录名（OpenChamberWidget 等）**本批不动**，在计划文档记为已知遗留（个人暂不发布移动端，避免大动 pbxproj）。

### 第 3 批：更新与服务安全化
- `packages/web/server/lib/package-manager.js`：默认禁用 hosted 更新检查与 npm/GitHub 版本查询（`checkForUpdates` 返回"无更新"），保留 `TASKHUNBER_UPDATE_API_URL` 类 env 覆盖口子供日后自建；`update` 自更新命令改为提示不可用；移除对上游 CHANGELOG.md 的抓取；去掉 installId/reportUsage 上报。
- `packages/vscode/src/bridge.ts` update-check 同样处理。
- electron-updater feed 指自己仓库（机制保留，无 release 即无更新）。
- README 安装一行命令、marketplace/badge/Patreon 链接、SECURITY 联系方式改为本地/占位说明；`.github/CODEOWNERS` → `jlu-lujing`；禁用 `release.yml` 中 npm publish、`vscode-extension.yml`、`mobile-release.yml` 发布 job（或以注释关闭），bot/org-gated workflows 本就自禁用，留注释说明。

### 第 4 批：Logo 与图标
- 新写 `TaskHunterLogo.tsx`（目标/准星 + 任务勾选的简洁 SVG，颜色走 theme token，风格贴近 minimalist 习惯）。
- 用同一 SVG 源生成：web favicon/PWA 各尺寸（sips）、electron `resources/icons` 源图（macOS 用 iconutil 生成 icns；ico 留给 electron-builder 打包时从 png 生成）、vscode assets、mobile assets（icon-foreground/background）。changelog-card 配色微调。

### 第 5 批：验证
- `bunx oxlint` 于改动过的 TS 路径；各 package 依次 typecheck/lint + focused tests（重点 `packages/ui`、`packages/web` server 测试——storage key/env 断言会随替换同批更新）。
- `bun run dead-code`（文件改名后）。
- 跑一次 `bun run build:web` 冒烟；桌面端只做到 typecheck + 配置校验（不打包签名）。
- 残留扫描：`grep -ri openchamber` 输出应只剩保护名单条目，逐条确认。

### 范围外（本计划不做，需要时另开）
- iOS Xcode target 目录/Widget 类名彻底改名；老数据迁移（若将来分发给他人再补）；relay/推送/Linear 自建；docs 部署仓库（`openchamber-website` 在本仓库之外）。

## 风险提示
- ui 包 i18n 12 语言 ×~600 行是最大替换块，纯机械；web server 1,500+ 处属功能性（env/路由/事件名），两侧同批改，靠包级测试兜底。
- `/api/openchamber/*` 路由改名同时影响已配对移动设备——个人自用无存量设备，直接改。
- 提交策略：按上述批次分多个 commit，方便回滚。
