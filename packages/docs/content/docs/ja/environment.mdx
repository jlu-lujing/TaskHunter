# 環境変数

TaskHunter は起動時にこれらの環境変数を読み取ります。スタートアップサービスでは、`taskhunter startup enable` がデフォルトで現在の環境をスナップショットするため、サービスに使わせたい変数を変更した後は再実行してください。

## OpenCode、Git、ターミナル用の変数

OpenCode、Git、ターミナル、[プロジェクトアクション](/ja/project-actions/)に API トークンやデータベースのアドレスなど独自の変数を渡すには、TaskHunter の起動前に export するのではなく、**設定 → 一般 → 環境変数** に追加します。値は TaskHunter を実行しているマシンのデータディレクトリにある `environment.json` に保存され、あなたのユーザーだけが読めます。設定画面に値が再び表示されることはありません。置き換えたり削除したりはできますが、読み返すことはできません。

- OpenCode は起動時に変数を受け取るため、変更後は再起動してください。設定画面に再起動のボタンがあります。
- `opencode service set env` で設定した変数も OpenCode に渡ります。重なる場合は設定画面の値が優先されます。
- Git、ターミナル、プロジェクトアクションには次回の実行時に反映されます。
- TaskHunter が OpenCode 自体のために設定する変数（パスワードや設定など）は、あなたの変数より優先されます。

プロジェクトごとの変数や、`direnv export json` のように変数を出力するコマンドは、**設定 → プロジェクト** で追加できます。[プロジェクト](/ja/projects/#プロジェクトの環境)を参照してください。

これらの変数は、自分で起動した OpenCode サーバーには渡りません。また、VS Code 拡張機能にはこの設定がありません。以下の変数はすべて、TaskHunter 自身が起動時に読み取ります。

## TaskHunter サーバー

### `TASKHUNTER_HOST`

TaskHunter Web サーバーのバインドアドレスです。他のマシンからアクセスできるようにするには `0.0.0.0` を使います。

### `TASKHUNTER_LAN_URL`

ネットワーク上の他のデバイスが TaskHunter に接続するためのアドレスです（例: `http://192.168.1.20:3000`）。ペアリングリンクと QR コードは、TaskHunter が自分で検出したアドレスの代わりにこれを使います。検出が間違う場合に設定してください。たとえば Docker では、TaskHunter にはコンテナ内部のアドレスしか見えません。

### `TASKHUNTER_UI_PASSWORD`

ブラウザ UI のパスワードです。localhost 以外にバインドする場合、トンネルを使う場合、またはリバースプロキシの背後で実行する場合に使います。

### `TASKHUNTER_UI_SESSION_TTL_HOURS`

「このデバイスを信頼する」がオフのときのブラウザのサインイン有効期間（時間）です。既定値は `12` です。

### `TASKHUNTER_UI_TRUSTED_SESSION_TTL_DAYS`

信頼したデバイスでのサインイン有効期間（日）です。既定値は `7` です。

### `TASKHUNTER_API_ONLY`

`true` または `1` に設定すると、TaskHunter をヘッドレスモードで起動します。デスクトップおよびモバイルクライアント向けの API ルートは利用できますが、ブラウザ UI は配信されません。

### `TASKHUNTER_FRAME_ANCESTORS`

自分のページのフレーム内に TaskHunter を表示できるオリジンをスペース区切りで指定します（例: `https://dash.example.com`）。`*` はすべてのサイトを許可します。既定では TaskHunter 自身とそのデスクトップ・モバイルアプリだけが埋め込めるため、他のサイトがボタンの上に重ねることはできません。

### `TASKHUNTER_DATA_DIR`

TaskHunter のデータディレクトリを上書きします。デフォルトは `~/.config/taskhunter` です。

TaskHunter が保存するものはすべてこのディレクトリ配下にあります: 設定、認証、プロジェクト設定、テーマ、プラン、音声モデル。バージョン 1.23 より前にカスタムディレクトリを使っていたインスタンスでは、初回起動時に `projects`、`themes`、`speech-models` フォルダーが `~/.config/taskhunter` からここへコピーされます。元のフォルダーはそのまま残り、マージはされません。

### `TASKHUNTER_CHATS_DIR`

プロジェクトを持たないチャット用に TaskHunter が作成する管理チャットディレクトリの場所を変更します。デフォルトは `~/.config/taskhunter/chats` です。TaskHunter と OpenCode を別のユーザーで実行している場合は、OpenCode サーバーが読み取れるディレクトリを指定してください。既存のチャットは移動されません。

### `TASKHUNTER_COMPRESS_API`

API レスポンス圧縮を制御します。`true` または `1` で強制的に有効化し、`false` または `0` で強制的に無効化します。

### `TASKHUNTER_SKIP_API_COMPRESSION`

`true` または `1` に設定すると API レスポンス圧縮を無効化します。これは `TASKHUNTER_COMPRESS_API` より優先されます。

### `TASKHUNTER_VERBOSE_REQUEST_LOGS`

`true` または `1` に設定すると詳細な HTTP リクエストログを有効にします。

### `TASKHUNTER_UPDATE_API_URL`

更新確認 API エンドポイントを上書きします。ほとんどのユーザーは未設定のままでかまいません。

### `TASKHUNTER_PACKAGE_MANAGER`

自動検出が間違っている場合に、更新操作で使うパッケージマネージャーを強制します。

## プロキシ

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

利用上限やスキルカタログなど、TaskHunter 自身が送るリクエストをプロキシ経由にします。小文字の変数名も使えます。`NO_PROXY` のホストは直接接続し、`localhost`、`127.0.0.1`、`::1` は常に直接接続するため、サインインのコールバックやローカルの OpenCode サーバーはそのまま動作します。

## OpenCode サーバー

### `OPENCODE_HOST`

TaskHunter を既存の OpenCode サーバーに接続します。値は明示的なポートを含み、パス、クエリ、ハッシュを含まない `http` または `https` の origin である必要があります。`OPENCODE_HOST` は `OPENCODE_PORT` より優先されます。

### `OPENCODE_PORT`

OpenCode サーバーのポートを設定します。管理対象 OpenCode では管理対象ポートの要求になり、`OPENCODE_SKIP_START=true` ではそのポートの外部サーバーに接続します。

### `OPENCODE_SKIP_START`

`true` に設定すると、TaskHunter が独自の OpenCode サーバーを起動しません。

### `TASKHUNTER_OPENCODE_HOSTNAME`

TaskHunter が管理する OpenCode サーバーのバインドホスト名です。デフォルトは `127.0.0.1` です。

### `OPENCODE_BINARY`

TaskHunter が実行する `opencode` 実行ファイルへのパスです。

### `OPENCODE_CONFIG`

特定の OpenCode 設定ファイルへのパスです。

### `OPENCODE_CONFIG_DIR`

エージェント、スキル、スニペット、設定検出に使う特定の OpenCode 設定ディレクトリへのパスです。

### `OPENCODE_DATA_DIR`

管理対象 OpenCode サーバーのカスタムデータディレクトリです。

### `OPENCODE_WSL_DISTRO`

Windows 上の OpenCode 連携に使う WSL ディストリビューションを選びます。

### `TASKHUNTER_OPENCODE_WSL_DISTRO`

WSL ディストリビューション選択用の TaskHunter 固有エイリアスです。両方が設定されている場合は `OPENCODE_WSL_DISTRO` が優先されます。

### `OPENCODE_JWT_SECRET`

UI 認証トークンの署名に使うシークレットです。永続的なサービス配置では長いランダム値を使ってください。

## ターミナルと Git

### `TASKHUNTER_TERMINAL_SHELL`

TaskHunter のターミナルセッションで使うシェル実行ファイルです。

### `TASKHUNTER_GIT_BINARY`

TaskHunter の Git 機能で使う Git 実行ファイルです。

### `GIT_BINARY`

代替の Git 実行ファイル上書きです。TaskHunter 固有の設定には `TASKHUNTER_GIT_BINARY` を推奨します。

### `TASKHUNTER_GIT_READ_CACHE_TTL_MS`

Git に基づくファイル読み取りキャッシュの有効期間（ミリ秒）です。デバッグ中にこのキャッシュを無効化するには `0` を設定します。

## 音声とトンネル

### `OPENAI_API_KEY`

TaskHunter の音声機能が OpenAI 本体を呼び出すときに使う API キーです。カスタムの OpenAI 互換サーバーには送信されません。そのサーバーには設定で専用のキーを指定してください。

### `TASKHUNTER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

`true` または `1` に設定すると、音声機能でリモートの OpenAI 互換 base URL を許可します。

### `NGROK_AUTHTOKEN`

TaskHunter のトンネルコマンドで使う ngrok 認証トークンです。`ngrok config add-authtoken <token>` で ngrok 側に設定することもできます。

## ランタイムヘルパー

### `BUN_BINARY`

デーモンプロセスを起動するときに TaskHunter が使う Bun 実行ファイルです。

### `BUN_INSTALL`

Bun のインストールルートです。TaskHunter はデーモン起動と更新のために `bin/bun` を探す際に使います。

### `VITE_OPENCODE_URL`

Vite でビルドされた Web アプリ向けのビルド時 API base URL です。通常の CLI またはデスクトップ利用では、ほとんどのユーザーは設定する必要がありません。
